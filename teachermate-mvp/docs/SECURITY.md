# TeacherMate 데이터베이스 보안 설계

> 작성: 2026-10-16 · 대상: MVP(2026.11) ~ 시범학교 파일럿(2027.1~2)
> 이 문서는 설계 기록이며 법률 검토를 대체하지 않는다. 파일럿 전에 개인정보 보호 전문가·교육청 정보보호 담당의 검토를 받는다.

## 1. 핵심 원칙: 지킬 데이터를 애초에 만들지 않는다

가장 강한 보안은 암호화가 아니라 **저장하지 않는 것**이다. TeacherMate는 사업계획서의 안전 원칙대로 다음을 DB에 두지 않는다.

| 저장하지 않는 것 | 대신 하는 것 |
|---|---|
| 학생 명단, 학번, 연락처, 성적, 상담·건강 정보 | 입력 단계에서 차단. 필요한 업무는 학교 안 원본 위치(NAS 경로)만 적는다 |
| 교사 실명 | 업무분장명(예: 6학년 부장, 정보 담당)으로 표기. 계정은 이메일만 |
| 붙여 넣은 공문·회의자료 원문 | 단계마다 근거가 된 **문장만** 저장 |
| AI에 보낸 본문과 AI 응답 | 저장·로그 없음. 글자 수와 시각만 `ai_usage`에 기록 |

이렇게 하면 DB가 통째로 유출되어도 나가는 것은 "학교 업무 일정과 요령"이다. 또한 학생 개인정보를 처리하지 않으므로 학습지원 소프트웨어 심의 대상이 아니라는 사업계획서의 진입 전략과도 일치한다.

## 2. 구조

```
[교사 브라우저] ──(anon key + 로그인 JWT)──▶ [Supabase Postgres + RLS]
      │                                              ▲
      │ (로그인 JWT)                                  │ service role (함수 안에서만)
      └────────▶ [Edge Function ai-flow] ────────────┘
                         │ (ANTHROPIC_API_KEY, 서버 시크릿)
                         ▼
                   [Anthropic Claude API]
```

- 브라우저에는 **anon key만** 있다. 공개되어도 되는 키이며, 실제 보호는 RLS가 한다.
- `service_role` 키와 AI 키는 Edge Function 시크릿에만 있다. `.env.local`, 프론트 코드, GitHub 어디에도 두지 않는다.

## 3. 다섯 겹의 방어

### ① 학교 단위 격리 (RLS)
모든 업무 테이블에 `school_id`가 있고, 정책은 `is_member(school_id)` 하나로 통일했다. 내가 속한 학교의 행만 읽고 쓸 수 있다. 화면 코드에서 `school_id`를 바꿔 요청해도 DB가 거부한다.

### ② 최소 권한
- 비로그인(`anon`)은 모든 테이블 권한을 회수했다.
- `memberships`에는 insert 정책이 없다. 학교 만들기(`create_school`)와 초대 코드 합류(`join_school`)는 검증 로직이 있는 RPC로만 가능하다. 스스로 다른 학교 관리자가 되는 경로가 없다.
- 초대 코드는 관리자만 만들고, 7일·30명 제한이 있다.
- 인수인계 카드 삭제는 작성자와 관리자만 한다.
- 완료 체크(`task_progress`)는 본인 것만 보고 쓴다.

### ③ 개인정보 다층 차단
같은 종류의 검사를 세 곳에서 한다. 앞단이 뚫려도 뒷단이 막는다.
1. 브라우저 `src/lib/piiGuard.ts` — 주민등록번호, 휴대전화, 명단 표 머리글, 번호+이름 목록(5줄 이상)
2. Edge Function — AI로 보내기 직전 재검사
3. DB 트리거 `guard_task`, `guard_card` — 주민등록번호·휴대전화 형식이 있으면 `PII_BLOCKED`로 저장 거부

### ④ 무결성 장치
- 행의 `school_id`는 바꿀 수 없다(`lock_school_id`).
- 다른 학교의 업무분장을 연결할 수 없다(`guard_duty_same_school`).
- 모든 텍스트 컬럼에 길이 제한, JSON 컬럼에 크기 제한.
- `security definer` 함수는 모두 `search_path = ''`로 고정해 함수 하이재킹을 막는다.

### ⑤ AI 경계
- 로그인 + 구성원 확인 후에만 호출된다.
- 학교별 하루 한도(기본 50회), 사용자별 시간당 한도(기본 10회). 사업계획서의 '연간 AI 크레딧' 구조로 그대로 확장할 수 있다.
- 본문 20,000자 제한, CORS 허용 출처 고정.
- 보내기 전에 화면에서 제공사 이름과 전송 범위를 알리고 매번 동의를 받는다.
- AI가 낸 근거 문장이 원문에 실제로 있는지 서버와 화면에서 두 번 검증한다. 없으면 '직접 대조 필요'로 표시한다.

## 4. 검증 결과 (2026-10-16)

`supabase/tests/`의 공격 시나리오를 PostgreSQL 16에서 실행했다.

| 시나리오 | 기대 | 결과 |
|---|---|---|
| 휴대전화 번호가 든 할 일 저장 | 거부 | `PII_BLOCKED` |
| B학교 교사가 A학교 할 일 조회 | 0건 | 0건 |
| B학교 교사가 A학교로 할 일 작성 | 거부 | RLS 위반 |
| B학교 교사가 A학교 할 일 수정 | 0건 | `UPDATE 0` |
| B학교 교사가 A학교 관리자로 직접 가입 | 거부 | RLS 위반 |
| 초대 코드로 합류한 교사가 조회 | 1건 | 1건 |
| 일반 교사가 초대 코드 생성 | 거부 | `FORBIDDEN` |
| 할 일의 school_id를 다른 학교로 변경 | 거부 | `SCHOOL_ID_IMMUTABLE` |
| 비로그인 조회 | 거부 | permission denied |

- [ ] AI 제공사 데이터 처리·보관 약관을 파일럿 전에 다시 확인하고 개인정보 처리방침에 반영

## 6. 아직 남은 과제

- **파일 업로드(PDF·HWP)**: MVP는 텍스트 붙여넣기만 지원한다. 파일을 받게 되면 Storage 버킷을 비공개로 두고, 추출 후 원본을 즉시 삭제하는 구조로 간다.
- **이름 탐지 한계**: 문장 속에 섞인 학생 이름 한두 개는 규칙으로 완벽히 막을 수 없다. 화면 안내와 교사 확인이 함께 필요하다.
- **감사 로그**: 누가 언제 무엇을 바꿨는지 기록(내용 제외)은 파일럿 단계에서 추가한다.
- **교육청 일괄 계약 단계**: 공공기관 도입 시 클라우드 보안인증(CSAP) 등 별도 요건이 붙을 수 있으므로, 해당 시점에 요건을 확인한다.
- **로컬 체험 모드**: localStorage는 암호화 저장소가 아니다. 샘플·시연 전용으로만 쓴다.
